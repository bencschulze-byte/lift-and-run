# Lift & Run

A single-user daily workout app: four 45-minute lifting days, two Zone 2 runs and one
Zone 5 interval session a week. Static site, no build step, no runtime dependencies. It
installs to an iPhone home screen, works offline, keeps its data in `localStorage`, and
(once connected) syncs to a private GitHub Gist.

- Heavy 5x5-style work on the four main barbell lifts, with linear progression.
- A 5RM calibration ramp the first time you meet a lift; every number is overridable.
- Calendar-anchored: Monday is always Day 1. A missed day is missed, not made up.
- Automatic 10% deload after three consecutive fails, and a deload week every 7th week.

## Run it locally

```
node tools/serve.mjs          # http://localhost:8080
node --test                   # the whole test suite
```

Nothing to install. Node 18+ for the test runner and the tools.

### Dev aids

- `?date=2026-09-21` pretends it is that date, so you can look at any day of the week.
- Settings has a **Force deload week** toggle for the same reason.

## Deploy to GitHub Pages

1. `node tools/bump-cache.mjs` — **do this every time.** It bumps the service worker
   cache version and rewrites its file list. Skip it and iOS will happily serve you the
   old app forever.
2. `git add -A && git commit -m "..." && git push`
3. In the repo: **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`**.

`sw.js` has to stay at the site root: a service worker can only control pages at or below
its own path. `.nojekyll` is there so GitHub Pages serves everything as-is.

## Install on the iPhone

1. Open the Pages URL in **Safari** (not Chrome - only Safari can install to the home
   screen).
2. Share → **Add to Home Screen**.
3. Open it from the home screen. It runs full screen with no browser chrome, and after
   one online visit it loads with airplane mode on.

To get an update after a deploy, open the app **twice**. The first launch notices the new
service worker and downloads the new files in the background; the second launch runs them.
That is normal service worker behaviour, not a bug. If it is still stubborn, remove it from
the home screen and add it again.

## Gist sync

Sync is optional. Everything works with it switched off; it exists so a second device can
see the same history, and so the data survives a lost phone.

1. On GitHub: **Settings → Developer settings → Personal access tokens → Fine-grained
   tokens → Generate new token**.
2. Give it **only** the `Gists: Read and write` account permission. No repository access.
3. Copy the token into **Settings → Gist sync** in the app and tap Connect. The first
   connect creates a secret gist called `lift-and-run.json` and remembers its id.
4. On a second device, paste the same token and the gist id shown on the first one.

The token is kept in `localStorage` on that device only. It is never written to the repo,
the gist, the exported JSON, or the console. Anyone who can read that browser's storage
can read the token, which is why **Disconnect** exists - it deletes it.

If you would rather not use a token at all, Settings also has **Export JSON** and
**Import JSON**.

## How the program is put together

```
index.html            app shell and iOS meta tags
manifest.webmanifest  standalone PWA manifest
sw.js                 service worker (cache-first shell, never caches api.github.com)
styles.css            the whole stylesheet
icons/                generated by tools/make-icons.mjs
src/
  engine/             pure functions, no DOM and no storage - the program itself
    defaults.js       the exercise catalog, the slots and the weekly template
    plates.js         loadable weights and plate breakdowns
    warmup.js         ramp sets
    calibration.js    the 5RM ramp state machine
    progression.js    linear progression, accessory double progression, deload weeks
    cardio.js         the Zone 5 ladder and heart-rate zones
    template.js       what today is, and what it will cost in minutes
    dates.js          ISO date helpers, Monday = day 0
  storage.js          the single JSON document, migrations, export/import
  session.js          finishing a session: bookkeeping on top of the engine
  sync.js             gist sync
  ui/                 one module per screen, plus timer.js
  app.js              hash router and bootstrap
tests/                node:test files mirroring src/
tools/                serve.mjs, make-icons.mjs, bump-cache.mjs
```

**To change the program, change `src/engine/defaults.js`.** The exercise catalog, the
menus behind each slot and the seven-day template are all data. The screens never hard-code
an exercise. Adding an exercise to the catalog makes it appear for existing installs too:
`normalize()` in `storage.js` merges new catalog entries into a stored document without
touching the choices already made in it.

The engine is pure, so every rule has a unit test and none of them need a browser:

```
node --test
```
